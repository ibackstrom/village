Village CSV pipeline

The CSV is a point-instancing contract for rebuilding the generated village with proxy or production assets in Houdini and Unreal Engine PCG.

Export

  1. Generate the village and choose the required building quantity.
  2. Open Menu → Export Houdini/Unreal CSV.
  3. The downloaded file contains buildings, individual wall segments, primary road segments, internal street segments, and river segments.

Coordinate and geometry contract

Axes
Right-handed, Z-up. The map becomes the XY ground plane. Screen Y is flipped during export, so rotations remain consistent in 3D.
Units
One CSV unit should be treated as one metre. For Unreal, multiply position and dimensions by 100 when working directly in centimetres.
Pivot
Every row is a center point. Proxy geometry should be centered in X/Y, rest on Z=0, and point along local +X.
Rotation
RotationYaw is degrees around +Z. Pitch and roll are currently zero.

CSV schema

ColumnMeaning
NameUnique row ID; also satisfies Unreal Data Table's required first column.
ElementTypebuilding, wall, road, or river.
BuildingNameBuilding class shown by map hover. Empty for roads, walls, and rivers.
AssetNameStable lookup key such as building_cottage, wall_city, road_primary, road_internal, or river.
PositionX/Y/ZWorld-space point position in metres.
RotationPitch/Yaw/RollEuler rotation in degrees.
SizeX/Y/ZProxy dimensions. Building Z values are useful default heights; replace them with production asset dimensions as needed.
SegmentLengthWall, road, or river segment length. Zero for buildings.
SegmentWidthWall thickness, road width, or river width. Zero for buildings.

Roads, walls, and rivers are exported as midpoint-oriented segments rather than a single curve. This makes the same CSV directly usable for proxies, instanced modular pieces, or conversion back into connected curves.

Houdini SOP workflow

  1. Save the CSV as $HIP/village.csv.
  2. Create a Geometry object and add a Python SOP.
  3. Paste the importer below. It creates points plus typed attributes.
  4. Add an Attribute Wrangle to create orient and scale.
  5. Split by s@element_type or s@asset_name, then use Copy to Points, an asset library, or an HDA.

Python SOP importer

import csv
import hou

geo = hou.pwd().geometry()
geo.clear()
csv_path = hou.expandString("$HIP/village.csv")

string_attrs = {
    "name": "Name",
    "element_type": "ElementType",
    "building_name": "BuildingName",
    "asset_name": "AssetName",
}
float_attrs = {
    "rotation_pitch": "RotationPitch",
    "rotation_yaw": "RotationYaw",
    "rotation_roll": "RotationRoll",
    "size_x": "SizeX", "size_y": "SizeY", "size_z": "SizeZ",
    "segment_length": "SegmentLength",
    "segment_width": "SegmentWidth",
}

for attr in string_attrs:
    geo.addAttrib(hou.attribType.Point, attr, "")
for attr in float_attrs:
    geo.addAttrib(hou.attribType.Point, attr, 0.0)

with open(csv_path, newline="", encoding="utf-8-sig") as stream:
    for row in csv.DictReader(stream):
        point = geo.createPoint()
        point.setPosition((float(row["PositionX"]),
                           float(row["PositionY"]),
                           float(row["PositionZ"])))
        for attr, column in string_attrs.items():
            point.setAttribValue(attr, row[column])
        for attr, column in float_attrs.items():
            point.setAttribValue(attr, float(row[column]))

Point transform wrangle

float yaw = radians(f@rotation_yaw);
p@orient = quaternion(yaw, {0, 0, 1});
v@scale = set(f@size_x, f@size_y, f@size_z);
s@name = s@asset_name;

Exact proxy sizes and names

Build every source proxy at 1 × 1 × 1 Houdini units. The CSV point scale supplies the final dimensions in metres. All proxies must use local +X as length/forward and local +Y as width.

Proxy typeSource geometry and pivotRequired packed primitive name
Standard buildingsBox: X/Y −0.5 to 0.5, Z 0 to 1. Bottom-center pivot.building_cottage, building_row_house, building_townhouse, building_workshop, building_hall, building_warehouse, building_corner_house, building_merchant_house
Special buildingsSame bottom-centered 1 × 1 × 1 box rule.building_market, building_church, building_castle
WallsBox: X/Y −0.5 to 0.5, Z 0 to 1. +X runs along the wall.wall_city, wall_castle
RoadsBox: X/Y −0.5 to 0.5, Z −1 to 0, so its top remains at ground level.road_primary, road_internal
RiverBox: X/Y −0.5 to 0.5, Z −1 to 0, or a 1 × 1 XY Grid at Z=0. +X follows flow.river

Names must match exactly, including underscores and lowercase letters. A mismatched name produces a point with no copied source piece.

Build the named source library

  1. Create one geometry branch per proxy listed above.
  2. Use a Name SOP on each branch to set the primitive name to the required value.
  3. Pack each branch with a Pack SOP while preserving name.
  4. Merge all packed branches. This merged stream is input 1 of Copy to Points.
  5. Connect the transformed CSV points to input 2 of Copy to Points.
  6. Enable Transform Using Template Point Attributes, enable Pack and Instance, and set Piece Attribute to name.

Proxy reconstruction

  • The source is always one unit. A building point with scale = {4, 6, 5} therefore produces a 4 m × 6 m × 5 m proxy.
  • For production buildings, map asset_name to packed primitives. Preserve the CSV size as a footprint check rather than automatically stretching final art.
  • For roads, walls, and rivers, the unit box produces immediate segment proxies with no additional math.

Walls in Houdini

  1. Use a Blast SOP with @asset_name=wall_city or @asset_name=wall_castle.
  2. For a fast blockout, copy the corresponding unit wall box to those points.
  3. For modular walls, use segment_length to calculate module count: max(1, round(segment_length / module_length)).
  4. Distribute modules from −half-length to +half-length along point-local X. Keep the original orient so corners follow the exported wall.
  5. Do not fill missing segments automatically; those gaps are city gates.

Roads in Houdini

  1. Separate road_primary and road_internal with Blast or Split SOPs.
  2. Use the thin unit road box for a direct proxy. The exporter supplies primary-road width and narrower internal-street width through size_y.
  3. For terrain roads, derive each segment's two endpoints in a Point Wrangle:
vector forward = qrotate(p@orient, {1, 0, 0});
v@end_a = @P - forward * (f@segment_length * 0.5);
v@end_b = @P + forward * (f@segment_length * 0.5);
  1. Create line primitives from end_a to end_b, then Fuse endpoints with a small tolerance.
  2. Use PolyPath or a For-Each Connected Piece loop to form road curves. Preserve segment_width as a width attribute.
  3. Ray the curves onto terrain, Resample them, and Sweep a flat profile. Use primary and internal roads as separate branches so their widths and materials remain different.

River in Houdini

  1. Filter points with @asset_name=river. River rows are now exported with midpoint, yaw, length, and width.
  2. For a blockout, copy the named river grid or thin box to the points. The pieces should meet end-to-end.
  3. For a continuous river, derive endpoints with the same VEX used for roads, create line primitives, Fuse endpoints, then use PolyPath.
  4. Resample and Smooth the centerline before sweeping a flat strip. Drive the strip's width from segment_width.
  5. Set the water surface at Z=0 or project it to the desired water elevation. Build the riverbed separately by lowering and widening a copy of the strip.

Unreal Engine PCG — step by step

This workflow uses a Data Table, lightweight marker actors, and a PCG graph. It avoids version-sensitive custom PCG C++ nodes and works well for an initial proxy pass.

1. Enable the required plugins

  1. Open Edit → Plugins.
  2. Enable Procedural Content Generation Framework (PCG).
  3. Enable Editor Scripting Utilities for the CSV import utility.
  4. Restart Unreal Editor when prompted.

2. Create the CSV row structure

Create the following C++ row type, or create an equivalent Blueprint Structure with the same names and types. The CSV headers deliberately match these properties. The first Name column is used automatically as the Data Table row key and is not declared in the structure.

#pragma once

#include "CoreMinimal.h"
#include "Engine/DataTable.h"
#include "VillagePointRow.generated.h"

USTRUCT(BlueprintType)
struct FVillagePointRow : public FTableRowBase
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadOnly) FString ElementType;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) FString BuildingName;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) FString AssetName;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float PositionX = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float PositionY = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float PositionZ = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float RotationPitch = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float RotationYaw = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float RotationRoll = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float SizeX = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float SizeY = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float SizeZ = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float SegmentLength = 0;
    UPROPERTY(EditAnywhere, BlueprintReadOnly) float SegmentWidth = 0;
};

3. Import the Data Table

  1. Copy the exported CSV into the Unreal project's Content folder or another source-data folder.
  2. In the Content Browser choose Import and select the CSV.
  3. Choose DataTable and select VillagePointRow as the row structure.
  4. Open the resulting Data Table. Confirm that building rows have ElementType = building and that wall and road rows have positive SegmentLength.

4. Build one marker actor

  1. Create an Actor Blueprint named BP_VillagePointMarker.
  2. Use a Scene Component as the root. Add an optional Editor-only Billboard so markers are easy to select.
  3. Add exposed variables: ElementType, BuildingName, and AssetName as Strings, plus SourceRowName as Name.
  4. Disable collision and hide the Billboard in game. The actor is source data for PCG, not final geometry.

5. Create the Editor Utility importer

Create an Editor Utility Blueprint or Editor Utility Widget named EUW_ImportVillageCSV with a Data Table variable and an Import Village button. Its button graph should do the following:

  1. Delete the previous import: Get All Actors of Class BP_VillagePointMarker; destroy actors carrying the VillageCSV tag.
  2. Read rows: Get Data Table Row Names, then run a For Each Loop.
  3. Resolve the row: Get Data Table Row using the current row name.
  4. Convert location: make a Vector from PositionX/Y/Z and multiply it by 100, because the CSV is metres and Unreal uses centimetres.
  5. Convert rotation: Make Rotator using RotationRoll, RotationPitch, and RotationYaw.
  6. Create proxy scale: make a Vector from SizeX/Y/Z. This is the correct actor scale only when the proxy mesh is exactly one metre along each local axis.
  7. Spawn marker: Spawn Actor from Class BP_VillagePointMarker with the converted location and rotation, then Set Actor Scale 3D to the proxy scale.
  8. Copy metadata: set the marker's exposed variables from the row.
  9. Add actor tags: add VillageCSV, the row's ElementType, and the row's AssetName. Convert strings to Name for actor tags.

The actor tags make the PCG graph simple and reliable: each branch can select exactly one asset class without requiring custom metadata code.

6. Prepare proxy meshes

  1. Create or import a one-metre cube whose local dimensions are 100 × 100 × 100 cm.
  2. Place its pivot at the bottom center: centered in X/Y, with the bottom at Z=0.
  3. Keep local +X as the forward/length direction. Wall and road segments are exported along local +X.
  4. Create separate materials for buildings, walls, primary roads, and internal roads so the reconstruction is easy to inspect.

7. Build the PCG graph

  1. Add a PCG Volume covering the village and create a PCG Graph.
  2. Add a Get Actor Data node. Set its Actor Selector to select actors by the VillageCSV tag and include BP_VillagePointMarker.
  3. If the selected actor data is not already point data in your Unreal version, pass it through To Point.
  4. Create branches using Get Actor Data filtered by each AssetName tag—for example building_cottage, wall_city, road_primary, road_internal, and river.
  5. Connect every branch to a Static Mesh Spawner. Assign the matching building mesh, wall proxy, or road proxy.
  6. For the first validation pass, use the one-metre cube in every branch. The marker's transform and scale should reconstruct the CSV dimensions exactly.
  7. Generate the PCG component and compare the proxy settlement with the browser map.

8. Replace proxies with production meshes

Production assets rarely measure exactly one metre, so calculate point scale from the desired CSV dimensions and the source mesh bounds:

Location = FVector(PositionX, PositionY, PositionZ) * 100.0f;
Rotation = FRotator(RotationPitch, RotationYaw, RotationRoll);
DesiredWorldSizeCm = FVector(SizeX, SizeY, SizeZ) * 100.0f;
Scale3D = DesiredWorldSizeCm / SourceMeshBoundsCm;

Use the dimensionless Scale3D ratio as point scale. Do not use centimetre dimensions directly as Unreal scale. For hero buildings, keep scale uniform and use the CSV dimensions only to select an asset that fits the footprint.

9. Roads, walls, and rivers

  • Fast proxy: spawn the one-metre cube using the exported segment transform. SizeX is segment length, SizeY is width/thickness, and SizeZ is proxy height. Use a flat plane or thin box for river.
  • Modular walls: replace each long wall proxy with repeated modules. Divide SegmentLength × 100 by module length, round to a whole count, and distribute instances along local +X.
  • Production roads: derive segment endpoints from midpoint, yaw, and half-length; merge endpoints within a tolerance; then create Unreal Splines for landscape projection and spline-mesh placement.
  • Production river: use the same endpoint reconstruction, merge the river segments into a spline, and drive water width from SegmentWidth × 100.
  • Gates: missing wall segments are intentional gate openings. Do not bridge gaps automatically unless the design calls for a gate asset.

10. Validation checklist

  • Castle, market, and church assets appear exactly once per exported footprint.
  • Roads, walls, and river segments point along local +X and do not need an extra 90° yaw correction.
  • Building proxies rest on Z=0 instead of being half buried.
  • The import is not mirrored. If it is, confirm that no additional Y-axis inversion was added in Unreal.
  • Re-importing first deletes actors tagged VillageCSV, preventing duplicate PCG source points.

Recommended production setup

  • Buildings: map each AssetName to one or more weighted meshes; use the CSV transform as placement and footprint validation.
  • Walls: use modular wall pieces aligned on local +X, or merge connected segments into splines and use a spline mesh.
  • Roads: convert connected segment endpoints to splines for terrain projection, grading, and spline-mesh generation.
  • Iteration: keep Name as the stable source key so regenerated data can update rather than duplicate existing proxies.

Commercial use and licensing

Watabou's official Procgen Arcana FAQ and generator page state that generated maps may be copied, modified, and included in commercial projects. Attribution is appreciated but not required.

Important distinction

  • Generated maps: commercial use is explicitly allowed by the creator's published output permission. Exported layout data is reasonably covered by the same broad permission, although CSV is not named separately.
  • The generator application/code: the public TownGeneratorOS source is an older version licensed under GPLv3. Commercial redistribution is possible only while complying with GPL source, notice, and licensing obligations.
  • This mirrored newer web build: the official repository says it lacks newer features, and the hosted build does not publish a clear project-wide license in the downloaded files. Do not assume the older repository's GPL automatically covers every newer file. Obtain Watabou's permission before commercially redistributing this modified generator itself.

This is a source-based practical summary, not legal advice. For a commercial release of the generator application—not merely its outputs—have counsel review the exact files and permissions.
